# 设计取舍与验证

## 面向什么任务

用户提供活动事实、品牌参考和内容要求，系统准备海报、平台文案、脚本及线下执行资料。产品目标是降低材料与版本管理负担，保留用户对事实、创意、预算和发布的控制。公开版没有验证真实省时、转化或收益。

## 为什么不用一次长提示词完成全部工作

来源、版本、图片、文字、预算和审批有不同生命周期。将它们保存为项目记录与独立产物，能在活动事实改变时指出影响范围、复用不变资产，并保留旧批准版本。模型负责生成和部分语义判断；金额计算、权限、版本与审批资格由确定性逻辑验证。

## Agent 与 Workflow 的边界

当前系统包含大量固定工作流与受控模型节点，并不是完全自主规划的通用 Agent。工具调用与生成预算需要明确授权；未知提交先查询原运行。不能仅凭角色数量描述为自主多 Agent 协作已验收。

## 性能处理

工程中遇到首屏代码集中、项目响应重复包含审计来源、隐藏标签加载和小缩略图使用完整海报画布的问题。已采用工作区分包、日常字段投影、展开后读取、进行中 GET 合并、240×320 缩略图和隐藏画布释放。

完整审核与导出仍使用1080×1440，完整快照按需读取。专项测试验证30批次列表4次读取、无完成态审核缓存、保留完整存储数据。画布像素数或响应体积变化不能直接当作整体速度改善百分比。

## 尚需补充的产品证据

真实使用者任务测试、通用模型基线对照、内容采纳和修改记录、知识检索评测、实际平板 FPS 与内存轨迹、生产视频服务及真实活动交付验收。添加功能不替代这些证据。
