# Dify 接入与绑定

这些 DSL 来自工作台的五应用架构。导出模板保留节点、输入输出和人工审核约束，但移除了原工作区绑定与凭据。**不是导入即能运行的整套账户备份。**

1. 在自己的 Dify 工作区配置文字模型供应商。模板中的模型名称为原节点配置示例，需选择账户实际支持的模型并检查结构化输出与参数。
2. 建立四个知识库，使用 `dify/knowledge/` 中合成文件开始验证，随后换成自己有权使用的资料。保持来源 ID、版本、计划/实际区分和未知值规则。
3. 导入 `research.yml`、`strategy.yml`、`topic.yml`、`content.yml`，检查提示词、Python 节点和 schema。内容应用包含海报、脚本、图文、复盘四个分支。
4. 将前四个应用发布为工作流工具，维持模板使用的工具名称，创建只读项目运行数据工具。模板总控内工具 provider_id 使用占位 UUID，需从选择器绑定自己的工具，不能直接沿用占位值。
5. 按 `dify/ark-tools/openapi.json` 重建方舟自定义工具，配置自己的 API 密钥。不要在源码或浏览器中填写密钥。视自己的方舟账户选择可用模型与版本，并同步工作台配置核验。
6. 导入 `orchestrator.yml`，逐项重新选择工具、四个知识库与 HTTP 节点配置。`dataset_ids` 是占位值，原加密绑定不随模板发布。
7. 验证只读快照返回、项目 ID 与版本一致性、来源引用、JSON 解析、失败信息及人工审核状态。先做最小样本，确认模型费用后再测试图像/视频。
8. 发布总控，在 `.dev.vars` 配置 `DIFY_WORKFLOW_API_KEY`、实际 `WOO_DIFY_WORKFLOW_ID` 和自己记录的 `WOO_DIFY_PUBLISHED_VERSION`。代码拒绝发布版本不一致，不自动回退到最新版本。
9. 后台执行器保持关闭。准备独立鉴权 token、调度器和关页恢复验收后，才能设置 `WOO_EXECUTOR_ENABLED=1`、`WOO_EXECUTOR_VERIFIED=1`。没有调度器，仅打开网页不会自动长期生产。

占位 provider_id 对应关系：末位 `1` 调研、`2` 策略、`3` 选题、`4` 内容与只读快照、`5` 方舟自定义工具；后四个知识库占位绑定需从 Dify 界面重新选择。工具的 API key 为运行环境变量引用，没有实际密钥。

项目资料、模型输出和跨平台运营数据可能包含隐私；本公开版只提供合成材料。检索节点存在不等于检索效果合格，应另外建立问题集并评估命中、引用和回答质量。
